# Inventory API 🥤

Простой REST API для управления складом напитков, написанный на **Node.js + Express**
с хранением данных в **PostgreSQL**.
Учебный проект, демонстрирующий построение CRUD-сервиса, валидацию данных,
работу с реляционной БД, конфигурацию через переменные окружения и
контейнеризацию через Docker Compose.

## 🛠 Стек

- **Node.js** + **Express 5** — веб-сервер и роутинг
- **PostgreSQL** — реляционная база данных
- **pg** — драйвер Postgres для Node.js (пул соединений)
- **dotenv** — конфигурация через переменные окружения
- **Docker + Docker Compose** — контейнеризация приложения и БД
- **nodemon** (dev) — автоперезапуск при разработке

## 🚀 Запуск

### Через Docker Compose (рекомендуется)

Поднимает приложение и базу одной командой:

```bash
# 1. Создать .env из шаблона
cp .env.example .env

# 2. Поднять всё
docker compose up --build
```

API будет доступен на `http://localhost:3000`, таблица и стартовые данные
создаются автоматически при первом запуске.

### Локально (своя БД Postgres)

```bash
# 1. Установить зависимости
npm install

# 2. Создать .env из шаблона и указать параметры подключения к Postgres
cp .env.example .env

# 3. Запустить
npm start        # обычный запуск
npm run dev      # режим разработки (автоперезапуск)
```

## ⚙️ Конфигурация

Переменные окружения (см. `.env.example`):

| Переменная   | Описание                  | По умолчанию |
|--------------|---------------------------|--------------|
| `PORT`       | Порт HTTP-сервера         | `3000`       |
| `PGHOST`     | Хост Postgres             | `localhost`  |
| `PGPORT`     | Порт Postgres             | `5432`       |
| `PGUSER`     | Пользователь БД           | `postgres`   |
| `PGPASSWORD` | Пароль БД                 | `changeme`   |
| `PGDATABASE` | Имя базы данных           | `inventory`  |

## 📚 API

Базовый префикс: `/api/drinks`

| Метод    | Путь                | Описание                       |
|----------|---------------------|--------------------------------|
| `GET`    | `/api/drinks`       | Получить все напитки           |
| `GET`    | `/api/drinks/:id`   | Получить напиток по `id`       |
| `POST`   | `/api/drinks`       | Создать напиток                |
| `PUT`    | `/api/drinks/:id`   | Обновить остаток (`stock`)     |
| `DELETE` | `/api/drinks/:id`   | Удалить напиток                |

### Модель напитка

```json
{
  "id": 1,
  "name": "Gorilla",
  "stock": 5
}
```

### Примеры запросов

**Получить все напитки**
```bash
curl http://localhost:3000/api/drinks
```

**Создать напиток**
```bash
curl -X POST http://localhost:3000/api/drinks \
  -H "Content-Type: application/json" \
  -d '{"name": "Red Bull", "stock": 50}'
```

**Обновить остаток**
```bash
curl -X PUT http://localhost:3000/api/drinks/1 \
  -H "Content-Type: application/json" \
  -d '{"name": "Gorilla", "stock": 99}'
```

**Удалить напиток**
```bash
curl -X DELETE http://localhost:3000/api/drinks/1
```

### Коды ответов

| Код   | Когда                                              |
|-------|----------------------------------------------------|
| `200` | Успешный `GET` / `PUT`                              |
| `202` | Успешное удаление                                  |
| `400` | Некорректные данные в теле запроса                 |
| `404` | Напиток с указанным `id` не найден                 |

## 📝 Заметки

- Данные хранятся в PostgreSQL; таблица `drinks` создаётся автоматически при
  старте, при пустой базе наполняется стартовым набором напитков.
- Все SQL-запросы параметризованы (`$1, $2`) — защита от SQL-инъекций.
- Запросы к БД используют пул соединений (`pg.Pool`).
